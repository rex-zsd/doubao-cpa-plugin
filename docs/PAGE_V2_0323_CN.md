# 0.3.23：插件页面第二版

实现提交为 `2734b20`，版本发布为 `49075af`。2026-10-26（UTC）在临时的官方 CPA v8.0.13 实例（与线上相同的镜像）上实测。

## 清理

### 对话

插件每开一个新任务（续聊的除外），都会在豆包账号里新建一个对话。实测豆包的对话列表（`/alice/conversation/list`）：已知的插件对话和其他对话，类型、创建场景、标签、扩展字段都相同，列表里也没有插件提交时带的本地对话标识。所以从列表里分不出哪些是插件建的。

0.3.23 起，插件在 Work 确认受理（ACK）一个新建对话时，把对话 ID 和时间记进 state 目录的 `plugin-conversations.json`。页面只删除记录里的对话：

- 删除超过所选天数、且没有运行中任务或可续聊会话在用的对话。可续聊会话保留 12 小时，期间不会被删。
- 删除走网页端同样的 IM 接口：`/im/conversation/batch_del_user_conv`，命令号 4171，对话类型 3，`delete_all` 始终为 false，每次最多 20 个。
- Work 确认删除后才从记录里去掉；被拒绝时记录保留。
- 记录写入失败时，这个对话不会进入记录，以后也不会被删。

0.3.23 之前建的对话不在记录里，页面不会动它们。

### 连接器

插件创建的连接器名称都以 `independent-http-tools-` 开头。页面按这个前缀识别，分为使用中、缓存和残留三类：

- 清理时，闲置的缓存交给连接器缓存回收，残留的直接断开。
- 只在没有任务运行时执行。清理过程中如果有任务开始，就中止，因为新任务可能已经建好连接器、还没来得及记下。
- 从不断开其他名称的连接器。

同一账号上还有别的插件实例时，它的连接器在这里也会被当成残留，所以不要在这种情况下清理。

### 上传的文件

通过插件文件接口上传的文件可以全部删除，删除后对应的文件 ID 失效。

## 刷新模型列表

页面重新读取豆包的模型清单，替换插件的模型列表；运行中的任务保留原来选定的模型。然后插件通过 CPA 的宿主回调读取自己的认证文件，加上刷新时间标记后写回（原有字段保留）。CPA 发现认证文件变化后会重新加载账号，并向插件重新取模型列表。

实测：刷新后 CPA 记录了认证文件变化并处理，模型列表正常。实测时豆包的模型没有变化，所以“新模型出现在 CPA 列表里”这一步没有实际验证到。

## 配置热生效

0.3.22 及更早的版本在服务运行时拒绝任何配置修改，CPA 会因此把插件标为无效，直到重载。0.3.23 的处理：

- 只改 `native_tools`：立即对之后开始的任务生效，运行中的任务保持原策略。
- 改 `state_dir` 或 `helper_path`：先挂起，等没有任务运行时再重开服务。页面会提示有待生效的配置。

实测：在临时 CPA 上就地修改 `config.yaml`，把 `native_tools` 改为 false，热重载后状态立即显示关闭；再改回 true，立即显示开启。日志中没有插件报错。
