# 原生会话持久化（0.3.32）

先前版本只在内存保存可继续的原生会话。重启后，虽然原任务的完成结果和幂等重放仍可恢复，新的下一轮会新建 Work 会话并回放完整可见历史。0.3.32 把仍可继续的会话索引保存到私有状态目录下的 `gateway-threads.json`。

## 保存与领取

- 索引绑定账号、设备，保存原生会话、模式、历史摘要、模型/工具配置摘要、上次使用时间和真实上下文用量。工具会话另保留原工作目录及 sandbox。
- 原生任务成功完成、最终结果落盘后，才发布新的可继续索引。索引写入失败不会丢弃已经完成且持久化的回答。
- 下一轮必须与已回答历史的前缀精确匹配。消费索引先经临时文件、文件同步、原子替换及目录同步落盘，再允许任务发出生成请求。并发或重生成不能共同领取同一个原生会话。
- 消费索引写盘失败时，返回 `state_persistence_failed`，不会发出生成请求。预检拒绝的请求不消费会话。
- 完成任务可按原有策略清理；索引独立保留，工具工作目录在仍被索引引用时不被清理。

## 恢复与兼容

恢复任务后、启动后台恢复任务及清理孤立工作目录前，加载会话索引。活动任务占用的会话、已被任务继续推进的旧历史不会重新变成可领取状态。恢复索引本身不发出生成请求。

保留原有 12 小时有效期和最多 128 个可继续会话的限制。账号/设备变化、历史或工具配置变化、工具路由策略不匹配、原工具工作目录缺失时，不复用原上下文。索引含私有会话标识及本地路径，文件权限为 0600；不保存消息正文、工具返回值或凭证。

旧任务回执不会反推缺失的索引。因此首次从 0.3.31 升级时，不会自动恢复升级前仅存在内存中的会话；升级后新完成的会话开始具备跨重启恢复能力。损坏或未知格式的索引会使初始化报错，避免猜测会话归属。

独立 loopback helper 也使用相同任务/会话恢复流程及 `provider.lock`，同一状态目录只允许一个 provider 实例持有。

## 验证

单元与竞态测试覆盖：跨重启恢复、源任务已清理后的恢复、原工作目录保留、旧分支失效、并发领取、写盘失败不生成、已完成回答的幂等重放，以及账号/设备、有效期、历史和路由变化。

真实 Work 验证使用隔离状态目录和独立设备，检查重启前后原生会话保持一致，下一轮只发送新增消息；工具验证还检查原 sandbox/工作目录、函数参数、真实工具结果及生成次数。具体结果记录在本次发布证据中。
