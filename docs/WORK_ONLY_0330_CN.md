# 0.3.30：API 请求统一使用 Work

普通聊天接受相同的模型选择参数，但在本地能力对测中，没有保持 Work 模式的推理表现。0.3.30 将所有插件 API 请求统一到 Work。

- 没有客户端函数或 `tool_choice=none` 时，直接在 Work 回答，保留原来的函数语义。
- 启用客户端函数时，继续使用 Work 的本地电脑运行时与现有工具转发。
- 已有 Work 会话继续只发送新增消息；旧版 chat 会话重新提交完整可见历史，在 Work 新建会话，清除旧上下文用量。
- Work 在接收前拒绝续聊时，仍可用完整历史新建 Work 会话。初始请求被拒绝不会改到普通聊天，已接收的生成不会因此重发。
- 模型、思考档位、完整历史、接口与客户端工具定义保持原有传递规则。

回归覆盖：首次无工具请求、Work 续聊、被拒续聊的完整重放、旧 chat 历史迁移、显式禁用函数、拒绝分类与禁止模式降级。完整 `go test -race ./...` 使用固定 Go 1.26.9 构建镜像通过；测试临时目录使用 tmpfs，以免部署主机的持久化磁盘延迟干扰模拟接口的超时断言。

发布只需热加载新版本 `.so` 与配套 helper。按现有部署流程在空闲边界备份旧版本、原子安装、触发配置热重载并核对加载版本；保留 0.3.29 回滚文件。

测速采用同一问题、同一思考档位、串行交替三次，分别测 low 与 max。可见正文统一按 `o200k_base` 计数，另报告字符/秒、首字等待和整次请求耗时；统一计数仅用于比较输出速度，不作为模型原生计费 token。
