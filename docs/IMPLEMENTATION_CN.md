# CPA 插件实现与验收

本实现以独立 Go 协议核心提供原生 CPA 插件。

交付范围：单账号，Chat/Responses 全历史，图片/文件输入和媒体工具结果，多工具批次，持久化任务绑定，增量可见文本，Linux amd64 动态插件、辅助程序、配置及文档。其他平台与多账号不在本轮验收内。

执行顺序：
1. 抽取独立核心包与原生 C ABI 插件；通过 CPA HTTP 桥接执行所有上游请求。
2. 增加内容块、文件资源和按账号隔离的上传缓存。
3. 增加任务日志、未上传工具批次恢复、断线/重启及不确定写请求处理。
4. 接入只包含可见答案的增量输出，明确不支持的预算与 usage。
5. 编译真实宿主和插件，执行官方 SDK 端到端与错误恢复回归，打包交付。

已审查的公开验收摘要保存在 `docs/evidence/`。私有请求、上游收据和登录会话保存在本地验收目录，不进入源码或安装包。

工具媒体结果：直接 MCP 图片/嵌入 PDF 实测不稳定，采用独立、有收据的 Work 媒体读取任务提取文本事实，再交回原任务；每个含媒体的结果多一次模型调用，不能承诺无损图像细节。

发现的宿主缺口：固定版本的 host.http.do/do_stream 默认跟随重定向，插件不能获得中间登录 Set-Cookie，也不能阻止上传授权跨主机重定向。隔离宿主增加兼容的 wire_profile.disable_redirects 开关，默认行为保持不变；插件显式使用开关。随交付提供宿主补丁及固定构建。
