# 0.3.24：原生工具提示词精简

实现提交为 `2ea0dec`，版本发布为 `1b87bc2`。2026-10-26（UTC）在隔离实例上做了改前改后对比实测。

## 改了什么

开启 `native_tools` 后，0.3.19–0.3.23 在每个新任务的提示词末尾，原样附上调用方每个可走原生的工具的完整说明和 JSON Schema，再加约 1,200 字的转发规则。以一次真实 Claude Code 请求的 32 个工具目录计：

| 工具 | 说明 | 参数结构 |
|---|---:|---:|
| Bash | 1,005 | 1,564 |
| Read | 790 | 740 |
| NotebookEdit | 619 | 940 |
| TaskStop | 378 | 366 |
| Edit | 360 | 552 |
| Write | 240 | 348 |

单位为字。合计约 8,000 字，每开一轮新任务都会重复带上。

豆包自带的这些工具与 Claude Code 同名同参，模型本来就知道怎么调用。0.3.24 的提示词只写三样：

- 调用方声明了哪些工具
- 每个工具会被原生转发的参数名，必填的加 `*`；沙箱逃逸参数不列出
- 与平台不同的规则：绝对路径、Read 的 offset 从 1 开始、Bash 的 timeout 单位为毫秒、只有声明了 run_in_background 才能后台运行、Glob 不加平台独有选项、TaskOutput/TaskStop 只用于返回的任务 ID、不得提权

连接器里仍保留完整定义。每个原生调用仍按调用方的 schema 逐项校验，不兼容的退回 MCP。

## 对比实测

同一个隔离实例，Orange 5.5，档位 7，真实 32 工具目录，客户端在本地真实执行读写，并逐字核对参数和文件内容：

| 用例 | 改前：原生调用 / 结果 / 耗时 / 提示词 | 改后：原生调用 / 结果 / 耗时 / 提示词 |
|---|---|---|
| 读→写→改→读 ×2 | 全部原生 / 正确 / 31.9、35.7 秒 / 13,002 字 | 全部原生 / 正确 / 40.2、31.0 秒 / 4,737 字 |
| 按 offset/limit 读 | 原生 / 正确 / 16.4 秒 / 12,402 字 | 原生 / 正确 / 21.5 秒 / 4,137 字 |
| replace_all 编辑 | 全部原生 / 正确 / 36.9 秒 / 12,602 字 | 全部原生 / 正确 / 28.8 秒 / 4,337 字 |
| 写入被客户端拒绝 | 原生 / 如实报错 / 21.3 秒 / 12,568 字 | 原生 / 如实报错 / 21.3 秒 / 4,303 字 |

去掉列表中的沙箱逃逸参数后，又用最终版本复测：

- Bash 两次，都走原生、命令一字不差、答案正确，耗时 25.8、14.1 秒
- 读→写→改→读一次，全部原生，正确，33.0 秒，提示词 4,703 字

结论：

- 走原生的比例没有变化，全部用例都只发起 1 次生成，没有被拒的工具调用。
- 提示词每个新任务少约 8,300 字，降幅约 64%。
- 耗时看不出差别，主要花在模型生成上。
