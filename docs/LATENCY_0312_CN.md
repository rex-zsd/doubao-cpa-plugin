# 0.3.12：不改变模型请求的收尾延迟优化

本地版本 0.3.12 继承 0.3.11 的工具路由优化，只调整插件收尾顺序和增加阶段计时。保持模型、思考档位、工具定义、提示词、上下文、并行策略和已接受生成的取消策略。

## 实现

此前 runNative 和 resumeNative 在返回已核验答案前，同步等待临时连接器断开和列表确认。现在先持久化最终答案并返回，随后在原来的受管理任务协程中继续清理。没有增加脱离生命周期的后台协程；Service.Close 仍等待收尾。待清理任务和目录不会提前回收，重启会继续确认清理；已发出但结果不确定的断开请求不会重复发送。清理失败不改变成功答案。

成功任务在返回前已经取消并等待旧工具通道及处理器退出，因此下一轮可以使用原会话和 sandbox。续聊缓存不再依赖 cleanup_confirmed；新一轮仍注册、提交并校验自己的独立连接器。恢复路径也明确等待旧通道退出后再公布答案，避免两个处理器抢占同一个 sandbox。

GATEWAY_TIMING 只记录任务 ID、阶段、elapsed_ms、duration_ms。阶段包括 task_start/task_recovered、connector_ready、upstream_ack_received、tool_call_ready、client_result_received、upstream_complete、final_ready/final_error、cleanup_start/cleanup_done/cleanup_pending；无工具正文另有 first_visible_text，拒绝错误路由另有 unavailable_tool。

elapsed_ms 从当前进程创建/恢复任务开始，duration_ms 为该阶段的耗时：tool_call_ready 和 final_ready 从本次 API exchange 开始；client_result_received 从工具交出开始；cleanup_done 从清理开始。upstream_complete 的 duration 包含本任务的客户端工具等待。ACK 日志代表观察到事件，接受状态仍由原逻辑验证并落盘。重启前工具交出时间未知时 duration_ms=-1。日志不包含提示词、参数、凭据或思考内容。

## 回归验证

Go 1.26 的 go test -race ./...、go vet ./... 和 Linux amd64 C ABI 构建通过。新增回归覆盖：

- 故意阻塞清理时，真实 native runner 已返回准确答案，磁盘上已有最终结果和待清理状态。
- 同请求重放复用原答案；立即续聊保持同会话、目录、sandbox、完整提示词和工具定义，以及实际上游 effort=7。
- 清理未完成时保留过期任务/目录，Service.Close 等待收尾完成。
- 清理失败仍返回并重放成功答案；未完成的挂起任务不被清理。
- 重启后恢复清理并立即重放答案，不重新生成，也不重发结果不确定的断开请求。
- 恢复的旧工具流未完全退出前不公布答案；退出后不再等待连接器清理。

## 线上短任务对照

部署前后均使用 doubao-orange-5.5、reasoning_effort=7 和同一套 32 个工具，要求一次 Bash 调用后回答实际回传的随机校验串。测试端模拟工具结果，不执行模型生成的命令。每组两次，全部正确。

| 版本 | 首次工具调用（秒） | 回传工具结果后的回答（秒） | 两段合计（秒） |
|---|---|---|---|
| 0.3.11，本轮重测 | 16.926 / 16.633 | 7.836 / 7.440 | 24.762 / 24.073 |
| 0.3.12 | 12.290 / 16.063 | 4.810 / 6.889 | 17.100 / 22.952 |

此次改动只从最终答案的等待中移除清理，不能用它解释首次工具调用的变化。样本少且包含上游生成波动，不能把整轮时间差全部认定为优化收益，也不能推导所有复杂任务的加速比例或质量结论。

四个完成任务的阶段日志分别显示，答案返回后清理另用 747、946、720、732 ms；这些等待已从答案返回路径移除。核验完成到持久化最终状态仅 11–12 ms。清理原有 35 秒超时上限仍保留，但不再阻塞答案；35 秒是配置上界，不是本轮观测值。

额外的集成验收使用两个顺序依赖的 Bash 调用：第一轮返回随机值，第二轮必须在参数中使用这个实际值，再返回另一个未在提示中给出的随机值。最终答案准确，缓存重放 32 ms 且逐字段相同，随后立即续聊正确复述两个实际值。检查持久化收据确认前后是同一会话，两次生成分别只提交一次，均保持 32 个工具、effort=7，错误路由计数均为 0。答案到达测试客户端时 cleanup_confirmed=false，随后清理全部确认。验收结束没有活动任务或待确认清理。
